# 🌐 API 服务模块：答辩话术与报告撰写指南

## 1. 核心设计理念（必背）
如果老师问：“为什么有了 Gradio 还要做这个 `api` 模块？”
*   **回答要点**：Gradio 是为了**演示和调试**，而 API 是为了**集成和落地**。
*   **话术**：“老师，Gradio 界面虽然直观，但它不适合被其他系统调用。我们设计这个 API 模块是为了将 T5 的摘要能力封装成标准的微服务。这样，无论是手机 App、浏览器插件还是新闻后台，都可以通过发送 HTTP 请求来使用我们的模型。”

---

## 2. 老师可能会问的问题 (Q&A)

### Q1: “你这个 API 支持高并发吗？如果很多人同时用怎么办？”
*   **背景知识**：深度学习模型推理很慢，并发高了会排队。
*   **高分回答**：“我们在架构设计中预留了 `InferenceEngine` 和异步接口（Async）。在真实部署时，我们会配合 **Gunicorn** 和 **Uvicorn** 这种 ASGI 服务器，利用 Python 的异步特性来处理大量的 I/O 等待。如果压力再大，可以横向扩展多个 Worker 进程。”

### Q2: “你提到的‘流式输出’是什么？有什么用？”
*   **背景知识**：就像 ChatGPT 那样一个字一个字蹦出来，而不是等全写完再显示。
*   **高分回答**：“流式输出（Streaming）能显著降低用户的**首字延迟（TTFT）**。对于长新闻摘要，用户不需要等几十秒看到结果，而是能立刻看到开头。我们在 `service_framework.py` 里定义了 `stream_tokens` 接口来实现这个功能。”

### Q3: “如何保证 API 的安全性？别人乱调怎么办？”
*   **背景知识**：API 鉴权。
*   **高分回答**：“我们在 `APIGateway` 中设计了 `authenticate_request` 方法。生产环境下，我们会采用 **API Key** 或者 **JWT (JSON Web Token)** 机制。只有通过校验的请求才会被转发给推理引擎，同时还会配合限流器（Rate Limiter）防止恶意刷接口。”

### Q4: “如果要换模型版本，需要重启服务吗？”
*   **背景知识**：热加载（Hot-Swapping）。
*   **高分回答**：“不需要。我们设计了 `ModelRegistry`（模型注册中心），它支持**热加载**。管理员可以通过管理接口下发指令，让服务在后台加载新的 Checkpoint，加载完成后自动切换流量，实现无缝升级。”

## 3. 需要具备的“装样子”知识点

1.  **RESTful API / JSON**：
    *   *用途*：最通用的网络接口格式。
    *   *话术*：“我们遵循 RESTful 规范，输入输出都采用标准化的 JSON 格式，方便前端解析。”
2.  **Pydantic**：
    *   *用途*：Python 里用来做数据校验的库（代码里用了 `BaseModel`）。
    *   *话术*：“我们使用 Pydantic 进行强类型校验，确保传进来的文本长度、参数类型都是合法的，防止模型报错。”
3.  **ASGI (Asynchronous Server Gateway Interface)**：
    *   *用途*：现代 Python Web 框架（如 FastAPI）的标准。
    *   *话术*：“为了支持流式输出和高并发，我们选择了基于 ASGI 标准的架构，而不是传统的 WSGI。”

## 4. 实验报告“未来展望”怎么写？（直接复制版）

建议在报告的“系统设计与实现”或“未来展望”章节加入：

### 6. 系统集成：从实验脚本到微服务

#### 6.1 API 服务化设计
为了提升模型的工程应用价值，我们设计了 `api` 服务模块（见 `api/service_framework.py`）。该模块采用了**分层架构设计**：
*   **网关层 (API Gateway)**：负责请求鉴权、限流与路由分发。
*   **逻辑层 (Inference Engine)**：封装了 T5 的 Tokenization 与 Beam Search 生成逻辑。
*   **存储层 (Model Registry)**：实现了多版本模型的热加载与显存动态管理。

#### 6.2 性能优化方向
未来的 API 部署将重点关注以下指标：
1.  **降低延迟**：引入 **vLLM** 或 **ONNX Runtime** 加速推理过程，将单次摘要生成时间从秒级降低至毫秒级。
2.  **弹性伸缩**：结合 **Docker Compose** 或 **Kubernetes**，根据实时请求量自动增减 API 实例数量。
3.  **监控告警**：接入 **Prometheus + Grafana**，实时监控 API 的 QPS（每秒查询率）、P99 延迟以及显存占用情况。

*   **态度**：强调“标准化”和“可扩展性”。
*   **核心词**：**微服务 (Microservices)**、**异步 (Asynchronous)**、**热加载 (Hot-Swapping)**。
